Uninformed and informed search

Overview

A problem-solving agent plans ahead by search: it simulates sequences of actions in a model of its environment until it finds one that reaches a goal. Uninformed strategies use only the problem definition; informed strategies, such as greedy best-first search and A*, also use an estimate of the distance to the goal (Russell and Norvig, 2021, p. 63).

Search problems

  • Applies to environments that are fully observable, deterministic and known.
  • Components of a search problem:
    • State space: the set of possible states of the environment.
    • Initial state: where the agent starts, for example in Arad.
    • Goal states: one or more states that count as success; the goal test checks for them.
    • Actions: the actions applicable in each state.
    • Transition model: the state that results from doing an action in a state.
    • Action cost function: the cost c(s, a, s′) of action a taking state s to state s′ (Russell and Norvig, 2021, p. 65).
  • A path is a sequence of actions; costs are positive and add up along a path.
  • Abstraction: removing irrelevant detail from the representation, while keeping it valid and useful (Russell and Norvig, 2021, p. 66).
  • Running example: drive from Arad to Bucharest; states are cities, actions drive to a neighbouring city, and the cost is the road distance (Russell and Norvig, 2021, pp. 63–65).
DefinitionSolution. A path from the initial state to a goal state; an optimal solution has the lowest path cost of all solutions (Russell and Norvig, 2021, p. 65).

Search trees, frontier and reached states

  • A search algorithm builds a search tree: the root is the initial state, each edge an action.
  • The state space may be finite while the search tree is infinite, because one state can be reached by many paths.
  • A node records its state, its parent, the action that generated it, and the path cost g(n) from the initial state.
  • States have no parents, depths or path costs; nodes do. Following parent links back from a goal node gives the solution.
  • Expanding a node generates a child node for each applicable action; the child's g is the parent's g plus the action cost.
  • A state is reached once a node has been generated for it, whether or not it has been expanded.
  • A strategy is defined by the order in which nodes leave the frontier:
    • priority queue: lowest evaluation function first (best-first search);
    • FIFO queue: oldest node first (breadth-first search);
    • LIFO queue, or stack: newest node first (depth-first search) (Russell and Norvig, 2021, p. 74).
  • Best-first search always expands the frontier node with the lowest evaluation function f(n); different choices of f(n) give the specific algorithms (Russell and Norvig, 2021, p. 73).
DefinitionState and node. A state is a description of a configuration of the world; a node is an element of the search tree that corresponds to a state (Russell and Norvig, 2021, p. 71).
DefinitionFrontier. The set of nodes that have been generated but not yet expanded (Russell and Norvig, 2021, p. 72).

Graph search and tree-like search

  • A repeated state arises when two paths reach the same state; a cycle, such as Arad to Sibiu to Arad, is a special case of a redundant path.
  • Ignoring repeated states can make a linear problem exponential: a chain of d states with two actions between each has d + 1 states but 2d paths.
  • Graph search remembers every reached state and keeps only the best path to each; best-first search with its table of reached states is a graph search.
  • Tree-like search does not check for redundant paths: less memory, but the same state may be examined many times (Russell and Norvig, 2021, pp. 74–75).
  • A compromise checks only for cycles by following parent links; it needs no extra memory.
  • The frontier is also called the open list; the closed list is the set of expanded states, which is the reached states minus the frontier (Russell and Norvig, 2021, p. 72).
  • Graph search can be exponentially faster than tree-like search, at the cost of memory.

Measuring search performance

  • Completeness: is it guaranteed to find a solution when there is one, and to report failure when there is not?
  • Cost optimality: does it find a lowest-cost solution?
  • Time complexity: number of nodes generated or expanded.
  • Space complexity: largest number of nodes stored at once (Russell and Norvig, 2021, p. 75).
  • Quantities used:
    • b: branching factor, the (maximum) number of successors of a node;
    • d: depth of the shallowest solution;
    • m: maximum number of actions in any path (may be infinite);
    • ℓ: depth limit, for depth-limited search;
    • C*: cost of the optimal solution;
    • ε: a positive lower bound on every action cost (Russell and Norvig, 2021, pp. 76–80).
  • Big-O: T(n) is O(f(n)) if T(n) ≤ k f(n) for some constant k, for all n greater than some n0 (Russell and Norvig, 2021, p. 1024).
  • A tree with branching factor b has bd nodes at depth d, so uninformed search cost grows exponentially with solution depth.

Uninformed search strategies

DefinitionUninformed search. A strategy that uses only the information in the problem definition, with no estimate of how close a state is to a goal (Russell and Norvig, 2021, p. 76).

Breadth-first search

  • Expands the shallowest node first; the frontier is a FIFO queue.
  • Uses the early goal test: a node is tested when it is generated.
  • Complete if b is finite; cost-optimal if all action costs are equal.
  • Time and space O(bd) when the goal test is applied as each node is generated; O(bd+1) if it is applied only when a node is expanded (a late goal test).
  • Memory is a bigger problem than time: with b = 10 and 1 kilobyte per node, depth 10 needs 10 terabytes (Russell and Norvig, 2021, pp. 76–77).

Uniform-cost search

  • Best-first search with f(n) = g(n); known as Dijkstra's algorithm (Dijkstra, 1959).
  • Spreads out in waves of equal path cost; uses the late goal test, which is essential to optimality.
  • Complete if every action cost is at least ε > 0; cost-optimal.
  • Time and space O(b1+⌊C*/ε⌋), which can be much greater than bd (Russell and Norvig, 2021, pp. 77–78).

Depth-first search

  • Expands the deepest node first; the frontier is a stack. Usually run as a tree-like search.
  • Not complete (it can follow cycles or infinite paths); not cost-optimal.
  • Time O(bm); space only O(bm), since only the current path and unexpanded siblings are stored (Russell and Norvig, 2021, pp. 78–80).

Depth-limited search

  • Depth-first search in which nodes at depth ℓ are treated as having no children.
  • Returns a solution, failure (no solution at any depth) or cutoff (a solution may lie deeper than ℓ).
  • Incomplete if ℓ < d; time O(bℓ), space O(bℓ) (Russell and Norvig, 2021, pp. 80–81).

Iterative deepening search

  • Runs depth-limited search with ℓ = 0, 1, 2, and so on, until the result is not cutoff.
  • Complete if b is finite; cost-optimal if all action costs are equal.
  • Time O(bd); space O(bd).
  • Regenerating upper levels costs little: with b = 10 and d = 5 it generates 123,450 nodes against 111,110 for breadth-first search.
  • The preferred uninformed method when the state space is large and the solution depth is unknown (Russell and Norvig, 2021, pp. 80–82).

Heuristics and greedy best-first search

DefinitionHeuristic function. h(n) is the estimated cost of the cheapest path from the state at node n to a goal state (Russell and Norvig, 2021, p. 84).
  • Informed strategies are forms of best-first search; greedy search and A* differ only in f(n).
  • For Romania, hSLD(n) is the straight-line distance to Bucharest (Arad 366, Sibiu 253, Fagaras 176, Rimnicu Vilcea 193, Pitesti 100, Bucharest 0) (Russell and Norvig, 2021, p. 85).
  • Greedy best-first search uses f(n) = h(n): it expands the node that appears closest to the goal.
  • On Romania it finds Arad, Sibiu, Fagaras, Bucharest, cost 450, which is 32 more than the optimal 418.
  • Not cost-optimal; tree-like version incomplete (it can loop between Iasi and Neamt); graph version complete only in finite spaces.
  • Worst-case time and space for the graph version are linear in the number of states; a good heuristic can reduce this to O(bm) on some problems (Russell and Norvig, 2021, p. 85).

A* search

  • Best-first search with f(n) = g(n) + h(n): the estimated cost of the cheapest solution through n (Hart et al., 1968).
  • Greedy search ignores the cost already incurred; A* adds it, so it avoids expanding paths that are already expensive.
  • The goal test is applied when a node is taken from the frontier, not when it is generated.

Admissibility and optimality of A*

DefinitionAdmissible heuristic. A heuristic that never overestimates the cost to reach a goal: h(n) ≤ h*(n) for every node n, where h*(n) is the true cheapest cost from n (Russell and Norvig, 2021, p. 86).
  • hSLD is admissible, because a straight line is the shortest route between two points.
  • A* is cost-optimal with an admissible heuristic. Proof by contradiction:
    • suppose A* returns a path of cost C > C*; then some node n on the optimal path is unexpanded, so f(n) > C*;
    • but f(n) = g*(n) + h(n) ≤ g*(n) + h*(n) = C*, by admissibility;
    • the two statements contradict each other (Russell and Norvig, 2021, p. 88).
  • A consistent heuristic satisfies h(n) ≤ c(n, a, n′) + h(n′); every consistent heuristic is admissible (Russell and Norvig, 2021, p. 88).
  • A* spreads out in contours of increasing f; with a good heuristic they stretch towards the goal.
  • With a consistent heuristic, A* expands all nodes with f(n) < C*, possibly some with f(n) = C*, and none with f(n) > C* (Russell and Norvig, 2021, p. 90).
  • Complete if every action cost exceeds some ε > 0 and the state space has a solution or is finite.
  • Time is often still exponential in solution length; memory, since all generated nodes are kept, is its main weakness (Russell and Norvig, 2021, pp. 90, 92).

Question 1Multiple choice

Which data structure holds the frontier in depth-first search?

Depth-first search always expands the newest, deepest node, so its frontier is a stack.
Question 2Multiple choice

What is the space complexity of depth-first tree-like search?

Depth-first search stores only the current path and the unexpanded siblings of nodes on it, so its memory is O(bm), linear in the maximum depth m.
Question 3Multiple choice

Breadth-first search has time complexity O(bd) in one formulation and O(bd+1) in another. What accounts for the difference?

With the early goal test (on generation) no node at depth d + 1 is generated, giving O(bd); the late goal test (on expansion) adds one more level, giving O(bd+1).
Question 4Multiple choice

Uniform-cost search is best-first search with which evaluation function?

Uniform-cost search (Dijkstra's algorithm) orders the frontier by path cost g(n), spreading out in waves of equal path cost.
Question 5Multiple choice

Depth-limited search with limit ℓ finds no solution, but some nodes at depth ℓ were not expanded because of the limit. What does it return?

Cutoff means a solution might exist deeper than ℓ; failure means there is no solution at any depth. Iterative deepening increases the limit while the result is cutoff.
Question 6Multiple choice

Which uninformed strategy is complete when b is finite, cost-optimal when all action costs are equal, and needs only O(bd) memory?

Iterative deepening repeats depth-limited search with limits 0, 1, 2, and so on, combining the small memory of depth-first search with the completeness of breadth-first search.
Question 7Multiple choice

In best-first search, what is the role of the table of reached states?

The reached table keeps the best path found to each state, so redundant paths are dropped; this makes best-first search a graph search.
Question 8Multiple choice

Greedy best-first search with the straight-line distance heuristic finds which path from Arad to Bucharest?

Greedy search expands the node with the lowest h: Sibiu (253), then Fagaras (176), then Bucharest (0). The path costs 140 + 99 + 211 = 450, which is 32 more than the optimal path of cost 418.
Question 9Multiple choice

During A* search from Arad, Bucharest is added to the frontier with f = 450 while Pitesti, with f = 417, is still on the frontier. What happens next?

A* applies the goal test only when a node leaves the frontier. Pitesti has the lower f, so it is expanded first and generates Bucharest with f = 418, which is then returned.
Question 10Multiple choice

A heuristic h is admissible if, for every node n, which condition holds? (h*(n) is the true cost of the cheapest path from n to a goal.)

An admissible heuristic never overestimates the cost to reach a goal. The condition h(n) ≤ c(n, a, n′) + h(n′) for every child n′ defines the stronger property of consistency.
Question 11Multiple choice

With a consistent heuristic and optimal solution cost C*, which nodes does A* never expand?

A* expands all nodes with f(n) < C*, possibly some on the goal contour f(n) = C*, and none with f(n) > C*.

Question 15Short answer

Distinguish a state from a node in a search tree.

Model answer

A state is a description of a configuration of the world, such as being in Arad. A node is an element of the search tree that records four things: the state it corresponds to, its parent node, the action that generated it, and the path cost g(n) from the initial state. States have no parent, depth or path cost. Because a state can be reached by several paths, the same state may appear in many nodes.

Question 16Short answer

Prove that A* search with an admissible heuristic is cost-optimal.

Model answer

Suppose the optimal path costs C* but A* returns a path of cost C > C*. Some node n on the optimal path must be unexpanded, so f(n) > C* (otherwise n would have been expanded first). But f(n) = g(n) + h(n) = g*(n) + h(n), because n lies on an optimal path, and admissibility gives h(n) ≤ h*(n), so f(n) ≤ g*(n) + h*(n) = C*. This contradicts f(n) > C*, so A* returns only cost-optimal paths.

Question 17Short answer

Compare greedy best-first search and A* search on the Romania problem, explaining why they return different paths.

Model answer

Greedy best-first search uses f(n) = h(n), so it expands the city that appears closest to Bucharest: Arad, Sibiu, Fagaras, Bucharest, a path of cost 450. It ignores the cost already incurred, so it is not cost-optimal. A* uses f(n) = g(n) + h(n), the estimated total cost of a solution through n. With the admissible straight-line distance heuristic it does not accept the path through Fagaras while Pitesti (f = 417) could still lead to something cheaper, and it returns Arad, Sibiu, Rimnicu Vilcea, Pitesti, Bucharest, cost 418.
