# Adversarial Search and Game Theory

## Summary
### Flow Summary
Lecture on adversarial search: recap of search categories, game theory and game trees, then the minimax algorithm and alpha-beta pruning, worked through a three-level example tree with root value 3.

### Recap of Search Categories
- Informed search uses heuristics (transcribed as 'theoristic') and suits observable, deterministic environments
    - Example: a traveler in Sri Lanka who knows the map
- Uninformed search covers DFS and BFS; know which uses a stack (LIFO) and which a queue (FIFO)
- Adversarial search is the third category; genetic algorithms and similar belong to computational intelligence, not this syllabus

### Adversarial Search and Game Theory
- Game theory goes beyond computer games, e.g. stock markets and Binance; each player aims to win against opponents
    - Good area for coursework or final year projects, e.g. a past student's Pac-Man game
- Recommended reading: AIMA (Artificial Intelligence: A Modern Approach), 4th edition, Chapter 6; examiners draw questions from its exercises
- Lecturer added about 5 or 6 figures and explanations to the slides on the dashboard not in the original lecture

### Game Trees and Zero-Sum Games
- Tic-tac-toe is a two-player, deterministic, perfect-information game: options are known even if moves are not
    - Utility: win +1, loss -1, draw 0 (0.5 each); zero-sum since utilities always sum to zero
- Chess game trees are infeasible to draw fully: board and pieces too large, early computers lacked memory
- Changing the environment (e.g. 3x3 to 4x4, 9 to 16 options) requires updating the game tree and makes it deeper
- Know root (no parent) vs leaf/terminal nodes; finding a winning action sequence requires the game tree

### Minimax Algorithm
- Max player starts and maximizes utility; Min player minimizes it; applies only to two-player deterministic games
- Key components: player, actions (legal moves), result (transition model), terminal test, utility/objective function
- Minimax is complete for finite trees, optimal against an optimal opponent; time O(b^m), uses depth-first exploration
    - Chess example: b = 35, m around 100, far too large
- Past exam twist: a tree with two consecutive minimizer levels caught many students out

### Alpha-Beta Pruning
- Extension of minimax (transcribed 'alpha beta proton/2'); prunes branches that cannot affect the result to cut search time
- Alpha starts at negative infinity (maximizer), beta at positive infinity (minimizer); prune when alpha >= beta
- Worked example: node B gives 3, node C pruned after seeing 2, node D goes 14, 5, 2; root value is 3
