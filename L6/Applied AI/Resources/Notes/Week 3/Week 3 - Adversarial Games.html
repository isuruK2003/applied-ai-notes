Adversarial search and games

Overview

Ordinary search assumes we are the only one making moves. In a game there is an opponent working against us, so we need adversarial search. The core method is the minimax algorithm, made faster by alpha-beta pruning. Real programs also have to cope with time limits, with chance, and with hidden information.

Kinds of games

Games differ in several ways:

  • Deterministic or chance-based: does luck, such as a dice roll, play a part?
  • Number of players: one, two or more.
  • Zero-sum or cooperative: is one player's gain always the other's loss, or can players work together?
  • Perfect or imperfect information: can every player see the whole game, or is something hidden?

Whatever the type, we need an algorithm that picks the next move in every position.

Two-player zero-sum games

These are the games AI has studied most, such as tic-tac-toe, chess and Go. They have five features:

  • No chance: nothing is random.
  • Two players: called MAX and MIN.
  • Taking turns: one player moves, then the other.
  • Everything visible: both players always know the full state of the game.
  • Zero-sum: whatever is good for one player is equally bad for the other.

MAX and MIN each try to find a strategy that leads to a win.

How games differ from ordinary search

The opponent is unpredictable

A fixed list of moves is not enough. The answer has to be a strategy: a move ready for every reply the opponent might make.

Time is limited

There is rarely time to search all the way to the end of the game, so the program has to make good guesses.

A brief history

  • 1846Charles Babbage considers how a machine could look ahead through possible moves.
  • 1912 and 1944Ernst Zermelo, and later John von Neumann, describe an algorithm for perfect play.
  • 1950Claude Shannon writes the first paper on computer chess, proposing a limited look-ahead and an estimate of each position.
  • 1951Alan Turing writes the first chess program, worked through by hand.
  • 1952–1957Arthur Samuel uses machine learning to improve how his checkers program judges positions.
  • 1956John McCarthy suggests pruning, so the program can search deeper.

The AI behind Deep Blue

IBM's chess computer Deep Blue lost its first match against world champion Garry Kasparov in February 1996, by 4 games to 2. It won the rematch in 1997, the first time a computer beat a reigning world champion in a match. At its core was minimax search with alpha-beta pruning, together with a very detailed way of judging positions and purpose-built hardware.

Game trees

A game tree shows every possible sequence of moves. In a two-player game its levels alternate between MAX's turn and MIN's turn. In tic-tac-toe the top of the tree is the empty board. MAX, playing X, has 9 possible first moves, MIN has 8 replies to each, and so on down to the finished games. Each finished game is scored −1 for a loss, 0 for a draw or +1 for a win, from MAX's point of view.

Describing a game precisely

To search a game, we describe it with six parts:

Starting state
How the game is set up at the beginning. It is written S0.
PLAYER(s)
Whose turn it is in state s.
ACTIONS(s)
The legal moves in state s.
RESULT(s, a)
The state you get by making move a in state s.
TERMINAL-TEST(s)
Whether the game is over in state s. States where it is over are called terminal states.
UTILITY(s, p)
The final score for player p when the game ends in state s. In chess, for example, a win scores 1, a loss 0 and a draw ½.

The minimax algorithm

Minimax plays perfectly in two-player games with no chance and nothing hidden.

Key pointChoose the move that leads to the position with the highest minimax value: the best score you can guarantee, assuming the opponent also plays as well as possible.

How to read the tree:

  • A triangle pointing up is MAX's turn. MAX picks the largest value below it.
  • A triangle pointing down is MIN's turn. MIN picks the smallest value below it.
  • a1, a2 and so on are the moves. The value at the top is the largest of the smallest values.

One move by one player is called a ply. This tree has two plies: one move by MAX, then one by MIN.

Pseudocode

function MINIMAX-DECISION(state) returns a move
    return the move a in ACTIONS(state) with the highest MIN-VALUE(RESULT(state, a))

function MAX-VALUE(state) returns a score
    if TERMINAL-TEST(state) then return UTILITY(state)
    v ← −∞
    for each next state s do v ← MAX(v, MIN-VALUE(s))
    return v

function MIN-VALUE(state) returns a score
    if TERMINAL-TEST(state) then return UTILITY(state)
    v ← +∞
    for each next state s do v ← MIN(v, MAX-VALUE(s))
    return v

MAX-VALUE and MIN-VALUE call each other in turn. The search goes depth-first all the way down to finished games, then passes the scores back up the tree.

How minimax performs

CompleteYes, if the tree is finite. Chess has rules to make sure games end.
OptimalYes, against an opponent who also plays perfectly. Against a weaker opponent MAX still does at least as well, but a different strategy might take advantage of the opponent's mistakes.
TimeO(bm)
MemoryO(bm), because the search is depth-first
Key pointMinimax is too slow for real games. In chess there are about 35 moves to choose from in each position, and a typical game lasts about 100 plies. Searching every possibility is completely impossible. Do we really need to look at every path?

Alpha-beta pruning

The number of positions minimax must look at grows exponentially with the depth of the tree. We cannot remove that growth, but in the best case we can halve the exponent.

Alpha (α)
The best score MAX is already guaranteed somewhere higher up the tree. MAX will not accept anything lower.
Beta (β)
The best score MIN is already guaranteed somewhere higher up the tree. MIN will not allow anything higher.
  • Alpha-beta pruning can skip single positions and whole branches of the tree.
  • It never changes the value at the top of the tree.
  • The branches it skips could not have changed the decision, so looking at them would have wasted time.

Worked example

StepWhat happens
1Look at move a1. The first value is 3, so this MIN node is worth at most 3. The next values are 12 and 8, which MIN would not choose, so the node is worth exactly 3. MAX is now guaranteed at least 3, so alpha becomes 3.
2Look at move a2. The first value is 2, so this MIN node is worth at most 2. MAX already has 3 from a1 and will never choose a2, so the other two values are skipped.
3Look at move a3. The first value is 14, so the node is worth at most 14. That is still better than 3, so keep looking.
4The next value is 5, so the node is worth at most 5. That is still better than 3, so keep looking.
5The last value is 2, so the node is worth 2. The top of the tree is the largest of 3, at most 2, and 2, which is 3. MAX plays a1.

The algorithm

function ALPHA-BETA-DECISION(state) returns a move
    v ← MAX-VALUE(state, −∞, +∞)
    return the move in ACTIONS(state) whose value is v

function MAX-VALUE(state, α, β) returns a score
    if TERMINAL-TEST(state) then return UTILITY(state)
    v ← −∞
    for each next state s do
        v ← MAX(v, MIN-VALUE(s, α, β))
        if v ≥ β then return v           ; MIN higher up will never allow this, so stop
        α ← MAX(α, v)
    return v

function MIN-VALUE(state, α, β) returns a score
    if TERMINAL-TEST(state) then return UTILITY(state)
    v ← +∞
    for each next state s do
        v ← MIN(v, MAX-VALUE(s, α, β))
        if v ≤ α then return v           ; MAX higher up already has something better, so stop
        β ← MIN(β, v)
    return v

How alpha-beta pruning performs

  • The result is always the same as plain minimax.
  • Looking at the best moves first lets it skip more. If the moves are in the perfect order, the time drops to O(bm/2), which means it can search twice as deep in the same time.
  • It is a simple example of a program reasoning about which calculations are worth doing.
  • Even so, 3550 positions is still far too many.
Good to knowIf the moves are in a random order, alpha-beta pruning looks at roughly O(b3m/4) positions. Real programs try the most promising moves first, such as captures, or the moves that were best in a shallower search, to get close to the ideal O(bm/2).

Coping with time limits

Real games have time limits, so the program cannot search to the end of the game. The usual approach is:

  • Stop early: replace the test for the end of the game with a cutoff test, such as a depth limit.
  • Estimate instead of scoring: replace the final score with an evaluation function that estimates how good the position is.
Key pointHow deep can a program look? Suppose a program has 100 seconds per move and can examine 10,000 positions a second. That gives 1 million positions per move, which is about 358/2. With alpha-beta pruning it can look 8 plies ahead, which makes a fairly good chess program.

Evaluation functions

In chess, a position is usually judged by adding up weighted features:

Eval(s) = w1f1(s) + w2f2(s) + … + wnfn(s)

For example, w1 = 9 and f1(s) = the number of white queens minus the number of black queens.

Counting pieces is not enough on its own. Two positions can have exactly the same pieces on the board, yet in one of them one side is clearly winning because of where the pieces stand or whose turn it is. A good evaluation therefore needs to capture more than the material on the board.

Good to knowTypical piece values are a pawn 1, a knight or bishop 3, a rook 5 and a queen 9. Programs also weigh king safety, pawn structure and how freely pieces can move. One known problem with stopping at a fixed depth is the horizon effect: a disaster can be pushed just past the depth limit, where the program cannot see it. A common fix is to keep searching positions where captures are still pending, until things settle down.

Games of chance

In games such as backgammon, chance comes from dice or shuffled cards. The game tree gains chance nodes between the players' turns. Each branch from a chance node is one possible roll or deal, with a probability.

The algorithm

Expectiminimax plays perfectly in games of chance. It works just like minimax, with one extra rule for chance nodes:

…
if it is MAX's turn then
    return the highest value of the next states
if it is MIN's turn then
    return the lowest value of the next states
if it is a chance node then
    return the average value of the next states, weighted by probability
…

The weighted average is the expected value: multiply each outcome's value by its probability, then add them up.

Good to knowChance nodes make the tree much wider. Backgammon has 21 different dice rolls each turn, so searching deeply is very expensive. Also, because values are averaged, the actual numbers matter, not just which is bigger. Rescaling an evaluation function can change the move it picks.

Games with hidden information

In card games, for example, you cannot see your opponent's cards.

  • We can usually work out a probability for each possible deal.
  • That makes it look like one big dice roll at the start of the game.
  • The idea: work out the minimax value of each move for every possible deal, then choose the move with the highest average value across all the deals.
  • Bridge programs approximate this by generating 100 deals that fit the bidding so far, and choosing the move that wins the most tricks on average.
Key pointEvery game needs its own carefully chosen techniques. No single algorithm suits every game.

Games in practice

Computers now play many games at world-class level:

  • Scrabble: the program Quackle beat a former world champion.
  • Poker: Libratus beat four of the world's best players over a 20-day match of no-limit Texas hold'em. Pluribus later beat five players at the same table.
  • Backgammon: TD-Gammon looks only two plies ahead but judges positions very well, and plays at world-champion level. It even changed how experts think the game should be played.
  • Video games: in 2019, DeepMind's AlphaStar, built with deep learning and reinforcement learning, beat expert StarCraft II players 10 games to 1.

Summary

Games are fun to work on, and the same ideas apply to dangerous real situations, such as nuclear standoffs. They teach several important lessons about AI:

  • Perfect play is out of reach, so programs must make good approximations.
  • It pays to think about what is worth thinking about, as alpha-beta pruning does.
  • Uncertainty limits how well we can score positions.
  • The best decision depends on what you know, not on the true state of the game.

A useful analogy: “Games are to AI as grand prix racing is to automobile design.” They are a demanding test bed that pushes forward techniques used far more widely.

Question 8Multiple choice

Question 9Multiple choice
