Uninformed and informed search

Overview

Many AI problems can be treated as search: finding a sequence of actions that leads from where you start to where you want to be. Search methods that know nothing about where the goal is are called uninformed search. Methods that use a rough estimate of the distance to the goal are called informed search, and include the widely used A* algorithm.

How tree search works

The computer explores possible situations, called states, one at a time. From each state it works out which states it can reach next. Working out the next states is called expanding a state.

function TREE-SEARCH(problem, strategy) returns a solution, or failure
    start the search tree with the starting state of the problem
    loop do
        if there is nothing left to expand then return failure
        choose a leaf node to expand, using the strategy
        if the node contains a goal state then return the solution
        else expand the node and add the new nodes to the search tree
    end

States and nodes

State

A description of one situation in the problem, such as one arrangement of the tiles in an 8-tile sliding puzzle. A state has no parent, children, depth or cost.

Node

An entry in the search tree. It stores a state, the node it came from (its parent), the action that led to it, how deep it is in the tree, and the total cost of the path so far, written g(n).

Expanding a node creates new nodes for every state reachable from it. The same state can appear in several nodes if there are different ways to reach it.

The fringe, also called the frontier, is the list of nodes that have been created but not yet expanded. Every search method is really just a rule for which node on the fringe to expand next.

Example: driving across Romania

How to compare search methods

A search method is defined by the order in which it expands nodes. We judge each method on four questions:

PropertyThe question it answers
CompleteIf a solution exists, is it always found? And if none exists, does the method say so?
TimeHow long does it take, measured by the number of nodes created?
MemoryHow many nodes does it need to keep in memory at once?
OptimalDoes it always find the cheapest solution?

Time and memory are described using a few letters:

b
the branching factor: the largest number of next states that any state can have
d
the depth of the shallowest solution
m
the greatest depth the tree can reach, which may be unlimited
l
a depth limit set by us
C*
the cost of the cheapest solution

Uninformed search, also called blind search, uses only the information in the problem itself. The five main methods are breadth-first search, uniform-cost search, depth-first search, depth-limited search and iterative deepening search.

Big-O notation

Big-O notation describes how the time or memory an algorithm needs grows as the problem gets bigger. It ignores constant factors and keeps only the part that grows fastest. For example, 3n² + 5n + 2 is written O(n²).

Depth-first and breadth-first search

Depth-first search

Always expand the deepest node on the fringe.

The fringe is a stack: last in, first out. New nodes go on the front.

Breadth-first search

Always expand the shallowest node on the fringe.

The fringe is a queue: first in, first out. New nodes go on the end.

Breadth-first search: how it performs

  • Complete: yes, as long as b is finite.
  • Time: 1 + b + b2 + … + bd + b(bd − 1), which is O(bd+1). This grows exponentially with d.
  • Memory: O(bd+1), because every node is kept in memory.
  • Optimal: yes, if every step costs the same.
Watch outMemory is the real problem. A computer can easily create nodes at 100 MB per second. Searching for a full day would need 8,640 GB of memory.

Depth-first search: how it performs

  • Complete: no. It can go down an endless path or loop forever. If it is changed to avoid revisiting states on the current path, it becomes complete for problems with a finite number of states.
  • Time: O(bm). This is terrible if m is much larger than d, although if there are many solutions it can be much faster than breadth-first search.
  • Memory: O(bm). It only grows in a straight line with depth, which is its big advantage.
  • Optimal: no. It may find a deep solution before a shallow one.
Good to knowHow fast breadth-first search runs out of memory. The figures below assume b = 10, one million nodes a second and 1 KB of memory per node. They are for a version of breadth-first search that checks for the goal when a node is created, rather than when it is expanded as described on this page.

Fixing depth-first search

There are three ways to deal with depth-first search's endless paths and breadth-first search's memory use:

  1. Set a depth limit: depth-limited search.
  2. Raise the limit step by step: iterative deepening search.
  3. Use a rule of thumb: informed search, described below.
DefinitionHeuristic. A rule of thumb that guides a decision using only part of the available information. In search, it is a hint about where the goal is likely to be.

Depth-limited search

This is depth-first search that stops at a set depth l: nodes at depth l are treated as if they have no children. It can end in three ways. It can find a solution. It can report failure, meaning there is no solution at all. Or it can report cutoff, meaning no solution was found within the limit.

function DEPTH-LIMITED-SEARCH(problem, limit) returns solution, failure or cutoff
    RECURSIVE-DLS(MAKE-NODE(INITIAL-STATE[problem]), problem, limit)

function RECURSIVE-DLS(node, problem, limit) returns solution, failure or cutoff
    cutoff-occurred? ← false
    if GOAL-TEST(problem, STATE[node]) then return node
    else if DEPTH[node] = limit then return cutoff
    else for each successor in EXPAND(node, problem) do
        result ← RECURSIVE-DLS(successor, problem, limit)
        if result = cutoff then cutoff-occurred? ← true
        else if result ≠ failure then return result
    if cutoff-occurred? then return cutoff else return failure

Iterative deepening search

Run depth-limited search with a limit of 0, then 1, then 2, and so on, until a solution is found.

function ITERATIVE-DEEPENING-SEARCH(problem) returns a solution
    for depth ← 0 to ∞ do
        result ← DEPTH-LIMITED-SEARCH(problem, depth)
        if result ≠ cutoff then return result
    end

Key pointWhy iterative deepening is a good default. It uses as little memory as depth-first search, yet like breadth-first search it always finds a solution if one exists, and finds the shallowest one when every step costs the same. Repeating the top levels looks wasteful, but most nodes are on the bottom level, so the extra work is small.
Good to knowHow much extra work. With b = 10 and d = 5, iterative deepening creates 50 + 400 + 3,000 + 20,000 + 100,000 = 123,450 nodes. A version of breadth-first search that checks for the goal as soon as a node is created makes 10 + 100 + 1,000 + 10,000 + 100,000 = 111,110, so iterative deepening does only about 11% more work. The version of breadth-first search described on this page checks for the goal only when a node is expanded, and creates 1,111,100 nodes, about nine times more than iterative deepening. Either way, iterative deepening saves a huge amount of memory.

ε is the cost of the cheapest single step. Look at the memory row: depth-first, depth-limited and iterative deepening search grow in a straight line with depth, while breadth-first and uniform-cost search grow exponentially.

Good to knowUniform-cost search. It always expands the node with the lowest path cost so far, g(n), so its fringe is kept sorted by cost. When every step costs the same, it behaves exactly like breadth-first search. It finds the cheapest solution for any positive step costs, and it is the same as A* with an estimate of zero everywhere.

Repeated states and graph search

If a search does not notice when it reaches the same state twice, a problem that should take a short time can take an extremely long time.

Graph search solves this by keeping a list, called closed, of states it has already expanded, and never expanding them again:

function GRAPH-SEARCH(problem, fringe) returns a solution, or failure
    closed ← an empty set
    fringe ← INSERT(MAKE-NODE(INITIAL-STATE[problem]), fringe)
    loop do
        if fringe is empty then return failure
        node ← REMOVE-FRONT(fringe)
        if GOAL-TEST(problem, STATE[node]) then return node
        if STATE[node] is not in closed then
            add STATE[node] to closed
            fringe ← INSERT-ALL(EXPAND(node, problem), fringe)
    end

Summary of uninformed search

  • Setting up a problem usually means leaving out real-world detail, so that there are few enough states to search.
  • There are several uninformed search methods, including breadth-first, depth-first and iterative deepening search.
  • Iterative deepening uses little memory and not much more time than the other methods.
  • Graph search can be far faster than tree search, because it never expands the same state twice.

Informed search: greedy search and A*

Best-first search

Give every node a score, using an evaluation function f(n) that estimates how promising it is, and always expand the most promising node. The fringe is kept sorted by this score. Greedy search and A* are two versions of this idea.

Greedy search: how it performs

  • Complete: no. It can loop forever, for example Iasi, Neamt, Iasi, Neamt. It is complete for finite problems if it checks for repeated states.
  • Time: O(bm), although a good estimate can make it much faster.
  • Memory: O(bm), because it keeps every node in memory.
  • Optimal: no.

A* search

The idea behind A* is to avoid expanding routes that are already expensive.

g(n) is the distance travelled so far to reach n.
h(n) is the estimated distance from n to the goal.
f(n) is therefore the estimated length of the whole route through n.

Why A* finds the shortest route

Admissible estimates

A* needs an estimate that never overestimates the real remaining cost. Such an estimate is called admissible.

DefinitionAdmissible estimate. An estimate h is admissible if h(n) ≤ h*(n) for every node n, where h*(n) is the true cost from n to the goal. The estimate must also never be negative, so it is 0 at the goal.
Straight-line distance is admissible, because no road can be shorter than a straight line.

Result: with an admissible estimate, A* always finds the cheapest solution when used as tree search.

Good to knowConsistent estimates. For graph search, which never expands the same state twice, the estimate must also be consistent: h(n) ≤ c(n, n′) + h(n′) for every neighbour n′ of n, where c(n, n′) is the cost of the step from n to n′. In words, the estimate can never drop by more than the cost of a single step. Every consistent estimate is also admissible. Straight-line distance is consistent, so on the Romania map A* finds the shortest route either way.

Contours

A* expands nodes in order of increasing f. You can picture it spreading out in bands, or contours, of equal f, much as breadth-first search spreads out in levels. On the Romania map, imagine bands at 380, 400 and 420 km spreading out from Arad and stretching towards Bucharest. The better the estimate, the more tightly the bands point towards the goal.

A*: how it performs

  • Complete: yes, unless there are infinitely many nodes with f no greater than the cost of the goal.
  • Time: exponential in the size of the estimate's error multiplied by the length of the solution.
  • Memory: it keeps every node in memory. This is its main weakness in practice.
  • Optimal: yes. Where C* is the cost of the cheapest solution, A* expands every node with f below C*, some nodes with f equal to C*, and no nodes with f above C*.

  • A* is widely used, for example in games, robots and route planners.

Question 16Short answer

Why does A* always find the shortest route when its estimate is admissible?

Model answer

Because the estimate never overestimates, f(n) = g(n) + h(n) is never more than the true length of the best route through n.
